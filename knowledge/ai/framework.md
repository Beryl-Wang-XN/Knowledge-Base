# AI 技术侧认知框架

> 本文件是 AI 知识库的**骨架地图**，所有知识条目都应能挂靠到某个模块。
> 框架会随认知深入而迭代，调整请记录在文末「版本记录」。

## 定位与深度锚点

- **服务对象**：MaaS TokenHub 产品经理（运营系统建设 / 商业 · 技术逻辑 / 增长策略）。
- **深度锚点**：不追求成为算法工程师，而是达到「**能理解技术选择背后的成本与商业含义，并据此做运营系统设计和商业决策**」的 PM 深度。
- **构建原则**：框架优先（先有全局骨架），填充顺序按近期实用性排序（B/C/D/G 优先）。
- **信息鲜度原则**：**所有模块（A–G，不止动态层）均以联网核实的最新信息为准**。AI 内置知识仅作背景理解，关键事实（模型规格 / 定价 / 榜单 / 厂商动态 / 技术方案）必须经联网验证后才可入库。

## 脊柱：一次推理请求的生命周期

理解「一条 API 请求进来 → 到 GPU 上算出 token 返回」这条链路，等于同时理解技术、性能与成本。

```
用户 API 请求
  │
① 接入层 ──── 鉴权 / 限流 / 【计费起点】
  │
② 调度层 ──── 排队 / 批处理(batching) / 路由到实例        ← 核心工作
  │
③ 推理引擎 ── Prefill(读入prompt) → Decode(逐个吐token)    ← 成本结构根源
  │           └ KV Cache 吃显存
  │
④ 执行层 ──── GPU 计算 / 显存占用 / 多卡并行
  │
⑤ 返回层 ──── token 流式输出 / 【计费结算】
```

**关键连接点**：③ 的 Prefill（吃算力）与 Decode（吃显存带宽）计算特性不同，
这直接决定了成本结构，也解释了定价中 input / output token 为何常常不同价。

## 七大知识模块

| 模块 | 名称 | 主题 | 优先级 |
|------|------|------|--------|
| **A** | 模型层 Model | Transformer/Attention、稠密 vs MoE、精度与量化、上下文窗口、能力评估 | 中（稳态） |
| **B** | 推理层 Inference | Prefill/Decode、KV Cache、Batching、推理加速、推理框架、TTFT/TPOT/吞吐 | 🔴 近期核心 |
| **C** | 算力层 GPU/Infra | GPU 特性(显存/算力/带宽/互联)、显存构成、利用率(MFU)、并行策略 TP/PP/DP | 🔴 近期核心 |
| **D** | 调度服务层 Serving | 请求调度/SLA、负载均衡/路由、弹性伸缩/冷启动、潮汐调度/混部/多租户 | 🔴 近期核心（主场） |
| **E** | 成本经济层 Economics | 成本构成、单位经济(每token/每请求)、降本杠杆、Token 计量与计费 | 🟡 深度锚点 |
| **F** | 竞品供应商格局 Landscape | 模型厂商、MaaS/云厂商、算力供应商、开源生态 | ⚪ 贯穿始终 |
| **G** | 模型档案库 Model Registry | 结构化模型档案（★核心资产，横跨 A·F，稳态字段 + 动态记录） | ★ 核心资产 |

### 模块深度标准

| 模块 | 深度 | 判断标准 |
|------|------|---------|
| A | 中 | 能说清模型类型/规模/精度对成本和能力的影响，不需推导数学 |
| B | 深 | 能定量理解加速手段带来的吞吐/成本变化，与工程师讨论方案 |
| C | 深 | 能算显存够不够、一张卡多少并发、利用率瓶颈在哪 |
| D | 深 | 能设计/评审调度策略，理解 SLA 与成本的权衡 |
| E | 深(应用) | 能搭出每 token 成本模型，反推定价空间 |
| F | 中(持续) | 能画版图、跟踪动态，判断选型与竞争态势 |
| G | 深(结构化) | 能维护可横向对比的模型档案，支撑选型与定价 |

## 模块 G：模型档案库设计

每个模型（GPT / Claude / DeepSeek / Qwen …）是一条结构化档案记录，按 5 组维度组织：

| 维度组 | 包含内容 | 服务什么 |
|--------|---------|---------|
| ① 身份 | 厂商、版本、发布时间、开源/闭源、模态 | 归类、检索 |
| ② 技术规格 | 参数量、架构(稠密/MoE)、上下文长度、精度 | 理解能力与成本来源 |
| ③ 能力评估 | 分维度打分(推理/代码/数学/中文/长文本)、擅长场景、口碑 | 选型、推荐 |
| ④ 商业属性 | 官方定价(in/out token)、我方售价、成本、毛利 | 定价与商业决策 |
| ⑤ 运营属性 | 供应商、部署方式(自部署/API转售)、延迟、稳定性、调用量 | 调度与运营 |

> 待确认扩展维度：合规/授权条款、限流配额、多语言支持等。
