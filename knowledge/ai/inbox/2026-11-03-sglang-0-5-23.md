## 是什么

Fridge003 于 2026-11-02 22:14:10 UTC 发布 **SGLang v0.5.23**。发布说明写本版包含 1007 个 PR、257 位贡献者。上一版 v0.5.22 的发布时间是 2026-10-19。

发布说明的「What's new」把这几件事放在前面。数字都是说明里的口径，回顾时再对到对应 PR 的测试条件：

- DeepSeek-V4.1 在 GB300 上，高负载 prefill 吞吐最高到 1.5 倍，3.2 万到 6.4 万 token 提示的首 token 延迟大约低 28%。
- 可选的低延迟模式：NVIDIA megakernel 与 AMD monokernel 把 DeepSeek-V4.1-Flash 的 decode 收成常驻融合内核。说明称单用户 decode 在 GB300 上最多快 44%，在 MI350X 上最多快 75%。
- DeepSeek-V4.1-Flash、GLM-5.3-Flash、gpt-oss 等 MoE，在 H200 上、8K 提示的首 token 提前 30% 到 58%。
- 可选的 Paged Experts，让放不进显存的 MoE 在单张消费级 GPU 上跑，说明称比 CPU offload 最多快 30 倍。
- 经 SGLang-TorchTPU 插件可在 Google TPU7x 上跑。
- 量化 MoE（FP8 与 NVFP4）可以用新的可选 LoRA 引擎挂适配器。

升级说明里和线上行为直接相关的几条：DeepSeek-V4 / V4.1 的对话编码改走 deepseek-recipe，SGLang 自己的 `encoding_dsv4.py` / `encoding_dsv41.py` 去掉了；DeepSeek-V4.1 的 decoder SWA bounded replay 在支持的 CUDA 配置上默认打开，和完整 prefill 数值不完全相同；PD 分离时 DeepSeek-V4.1 默认 MegaAttention，prefill 和 decode 要一起升，否则旧 decode 读不了新的握手字段。`tokenspeed_mla` 后端移除，`--speculative-skip-dp-mlp-sync` 移除。

新模型表列出 Muse Spark Open、Beam-1.0、MiniMax-M3.1-Flash、MiniCPM-V 4.7 等。这些模型本身不是本窗口的新发布，只是本版写明可以跑。

猜测挂靠：B（推理框架、prefill / decode、投机解码）。不另写框架综述。
