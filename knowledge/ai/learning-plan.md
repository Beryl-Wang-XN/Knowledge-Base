## 每日机制（双轨制，20-30 分钟/天）

```
今日学习
├─ 🅰 主轨·学习(15-20 min) ── 按计划推进当前模块（稳态知识）
└─ 🅱 副轨·情报(5-10 min) ─── 联网拉过去 24h 行业更新（动态信息）
```

**两轨联动规则**
- 副轨每条更新尝试**挂回框架某模块**（如降价→E/G，新模型→G）。
- 挂不上/暂无关的进 `inbox/`（待归类暂存区），定期回顾，不强行消化。
- 与用户业务强相关（对标友商/供应商动态）**特别标记**提醒。

**每日流程**
1. 报告上次学习进度（读打卡表）。
2. 确认今天状态（学习 / 跳过）。
3. 副轨：联网拉更新 → 择要挂框架 / 进 inbox。
4. 主轨：推进当前模块今日份（约一个知识点，控制在 20 分钟内）。
5. 收尾：更新 `progress.md` 打卡表。

**更新拉取的能力边界（重要）**
- AI 无后台自动运行能力，仅在对话时可联网。每日更新有两种实现：
  - **方式一 · 会话触发**（默认，已选定）：用户每天说"开始今天的学习"，当场联网拉取 + 推进。免费即时，依赖主动发起。
  - **方式二 · 定时自动化**：建每日 Automation 定时任务，自动拉当天更新入 `inbox`，用户有空再看。防止忙时断档。

> **待办**：步骤 4（数据结构）完成后，将"每日要做的事 + 交互流程 + 数据操作"固化为 **skill**，使方式一（主动触发）与方式二（定时任务）复用同一套流程。

## 打卡确认原则

- 维护 `progress.md`，每日记录：日期 / 是否学习 / 学了什么 / 情报要点。
- 每次会话先报上次进度、问今天状态，形成闭环。
- 跳过的日子如实记录，不虚记。
