## 每日机制（双轨制，20-30 分钟/天）

```
今日学习
├─ 先回顾 inbox（8:00 已放入的情报，加上上次留下的）
├─ 你点名今天要学的回顾项
└─ 加上计划里的下一课 → 一起核实 → 每日页 + 小红书草稿 + 播客
```

**每日页学的是什么**
- **一页里有两部分**：计划里的下一课，加上你当天点名的回顾项。不是把库里旧条目再推一遍，也不是把队列里没点名的情报全部塞进今天。
- 写之前用一手源核实。下一课落成完整条目；点名的回顾项写入它挂靠的条目或模型档案，再提炼进同一张每日页。
- 8:00 的定时任务负责把过去 24 小时的情报放进 inbox。学习会话不再另拉一轮进队列。
- `daily/_sample.md` 是版式样例，不代表某一次正式学习。

**两轨联动规则**
- 副轨每条更新尝试**挂回框架某模块**（如降价→E/G，新模型→G）。
- 挂不上的按 `_templates/inbox.md` 进 `inbox/`。与用户业务强相关（对标友商/供应商动态）**特别标记**提醒。
- 看完每日页可以在同一次对话里追问。讲清当天内容的，写回条目。值得以后单独学的，写入「从回顾排入的课」，inbox 标 `promote`。暂时归不进模块的，进 inbox 标 `open`。当场能回答的追问不进 inbox。

**每天从回顾开始**
- 待回顾 = `open`，或 `later` 且已到 `review_after`。已写入下面「从回顾排入的课」的 `promote` 不再每天重列。
- 学习日先列出待回顾，并说出计划里的下一课。你点名哪些回顾项今天一起学。可以不点。
- 没点名的，你逐条说一个结果：不管了（`dropped`）、写到学习计划里（`promote`，追加到下面的列表）、留在回顾里下次处理（保持 `open`）。
- 然后只对「下一课 + 今天点名的回顾项」联网核实，生成每日页、小红书草稿和播客。队列不用清空。

**每日流程**
1. 报告上次学习进度，列出待回顾标题，并说出计划里的下一课。
2. 确认今天学习还是跳过。学习则等你点名今天的回顾项，并处置其余各项。
3. 联网核实下一课和点名项。不把没点名的写成内容，也不另拉一轮 24 小时情报。
4. 写入条目或模型档案。点名项改为 `merged`。
5. 呈现：把今日卡片、点名的回顾和 quiz 写入 `daily/YYYY-MM-DD.md`，另写小红书文案与播客口播稿。播客先运行 `python3 scripts/synthesize_podcast.py` 按 `kb.config.yaml` 的晓晓音色合成同名 m4a，再运行 `python3 scripts/build_site.py ai`。小红书文案写完后，在已登录的 Chrome 创作服务平台预填草稿，可见范围设为仅自己可见，暂存离开，不点发布。同一条音频预填进小宇宙草稿，不点发布；账号未完成主体认证时停下来等用户自己认证。格式见 `_templates/daily.md` 与 skill `ai-kb-daily` 的 `references/presentation.md`。
6. 收尾：更新 `progress.md` 打卡表，给出每日页地址，停下来等追问。`kind: sample` 的样例页不记入打卡。

**更新拉取的能力边界（重要）**
- 对话里只有用户发起才跑完整学习。情报拉取有两种实现：
  - **方式一 · 会话触发**：用户说「开始今天的学习」。从 inbox 回顾开场，把点名项和计划下一课核实后写成每日页并打卡。
  - **方式二 · 定时自动化**（2026-10-21 已启用）：每天 8:00 只把过去 24 小时的更新写入 `inbox/`。不生成每日页。这些条目留到下一次学习时由用户点名。

方式一的完整流程已写在 skill `ai-kb-daily`。方式二不跑这套完整流程。

## 打卡确认原则

- 维护 `progress.md`，每日记录：日期 / 是否学习 / 学了什么 / 情报要点。
- 每次会话先报上次进度、问今天状态，形成闭环。
- 跳过的日子如实记录，不虚记。
