# 口播稿 · KV Cache 决定一张卡能接多少人

分段标题不朗读。文末横线之后的说明不朗读。

## 【开场】

今天的正课只有一件事：KV Cache 为什么占显存，以及这怎么变成一张卡能同时接多少请求。后面再用三则今天点名的消息，看这件事在供应商和渠道上分别长什么样。

## 【缓存是用空间换时间】

大模型向外一个字一个字生成。每生成一个新字，都要和前面所有字做注意力。注意力要用每个历史字的 Key 和 Value。如果每一步都把历史重新算一遍，算量会随长度平方涨上去，慢到不能用。

所以推理系统把已经算过的 Key 和 Value 留下来。下一步只算新字的那一对。这就是 KV Cache。它让生成跑得动，代价是这些向量一直坐在显存里。输出有多长，请求进来的时候并不知道，所以这份缓存会变长，而且变到哪一步事先说不准。

## 【装下模型，还不等于能接客】

vLLM 论文给过一个 OPT-13B 的算法。单个 token 的 KV Cache 大约 800 KB。一条最长 2048 token 的请求，这份缓存最多大约 1.6 GB。在 A100 40GB 上跑 13B，大约 65% 的显存给权重，大约 30% 给 KV Cache，剩下是激活之类。

权重是固定的。缓存是跟着每条请求、每个已经生成的字往上长的。所以一张卡装下模型之后，还能再接几路，看的是剩下的显存够不够放这些缓存。限制并发的，常常不是「模型太大」，而是「缓存把空位占满了」。

## 【预留一整块，为什么浪费】

旧的管法是按这条请求可能的最大长度，预先占一整块连续显存。用户往往写不到那么长，占住的空位又不能借给别人。论文把浪费分成三类：为还没生成的字预留的槽、按最大长度多占的内部碎片，以及分配器因为请求长短不一留下的外部碎片。

测下来，真正存着 token 状态的，只有 KV Cache 那部分显存的 20.4% 到 38.2%。也就是六成到八成空着。

PagedAttention 的做法像操作系统分页。把每条请求的缓存切成固定大小的块，用到再领，不必连成一整片。逻辑上还是一条连续的对话，物理上可以散落。论文说，浪费主要只发生在每条请求的最后一块里，实践中低于 4%。默认一块装 16 个 token。

这里有个容易听反的地方。PagedAttention 的注意力 kernel，比 FasterTransformer 慢 20% 到 26%。它赢的不是单步算得更快，而是同一张卡能同时放进更多请求，端到端吞吐上去了。论文写，相对 FasterTransformer 和 Orca，相同延迟下吞吐大约 2 到 4 倍。

## 【这和报价有什么关系】

缓存利用率从两到四成提到 96% 以上，等于同一张卡能服务的请求数上去了。请求数上去，每 token 分到的卡时就下来。所以选型推理引擎，看的是它怎么管缓存，不是只看参数量。

还有一个产品侧的杠杆。固定的系统提示、同一次并行采样，可以共享已经算过的前缀。论文里，并行采样省下 6.1% 到 30.5% 的相关显存，束搜索省 37.6% 到 66.3%，具体看数据集。这就是缓存命中可以单独定价的技术理由。命中了，就不必把那段提示的预填充再烧一遍。

## 【今天的三则消息】

第一则是 DeepSeek 的推理框架 DeepInfer。官方 README 说，这次开源的是大规模线上服务用的框架，许可证 Apache 2.0，当前模型是 DeepSeek-V4.1-Flash，硬件写到 NVIDIA SM100 和华为昇腾 950。完整的在线服务还缺三块，官方写明没有放出来：KV cache 系统，视觉编码、预填充、解码这三段的分离交付，以及副本之间的负载均衡。

他们的部署问答里有自己的线上数字：一个集群每天 155 万亿 token，谷值定价下每 GPU 小时收入 38 美元。设计上，预填充用普通 8 卡机器，解码用 64 到 128 卡的超节点，KV cache 希望留超过 72 小时。实践里最小的高效单元，大约是 64 卡预填充加 64 卡解码。这些是 DeepSeek 自己说的，不是我们复现过的收益。对我们有用的结论更窄：想把他们的线上引擎整套接进来，现在这个开源包还不够，缓存和均衡还在他们自己的基础设施里。

第二则是 NVIDIA 的 OpenShell。10 月 21 日的新闻稿说参考架构已经可用。三层：Vera Rubin 跑模型，Vera CPU 跑工具和 harness，BlueField-4 上的 Sentry 做监控和策略执行。新闻稿里的 30 倍每兆瓦吞吐、相对 x86 的 2 倍、最多 20% 的容量，都是厂商自己的说法，先不要写进成本表。

文档里和我们更近的是推理入口。沙箱里如果访问 api.openai.com 这种外部地址，跟别的出网一样，由网络策略放行或拒绝。如果走 https://inference.local，网关会去掉调用方自己带的凭证，再注入已经配置好的供应商凭证。同一个网关下，所有沙箱看到的是同一个供应商、同一个模型。Baseten、DeepInfra、Fireworks、Together AI 被点名正在把这套架构接进流水线。对 TokenHub，要问的是密钥在不在智能体进程里。文档写的是不在。

第三则是渠道。同一天，OpenAI 宣布前沿模型和 Codex 的智能体流程将进入 Google Cloud 的 Model Garden。购买走 Marketplace，已有的 GCP 承诺额度可以拿来抵。一般可用写的是未来数周。公告没有型号清单，也没有价格，并写明 Microsoft 仍是主要云合作方。Google 自己的博客另列了 GPT-6 的几个名字。那是 Google 页面上的名字，不替换我们档案里已经核实过的 GPT-5.6 直连牌价。多一个采购入口，先记成「还没标价的渠道」，不要当成已经能下单的价目表。

## 【收束】

下次看一张卡的报价，先问两句。权重装下之后，还剩多少显存给 KV Cache？这份缓存是按最大长度占死，还是按块现领？问完，并发和每 token 成本才有分母。供应商如果只给你一个吞吐倍数，先把对比基线要来，再决定进不进成本模型。
