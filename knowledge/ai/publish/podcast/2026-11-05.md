# 口播稿 · 输出贵，是因为生成在串行

分段标题不朗读。文末横线之后的说明不朗读。

## 【开场】

今天的正课是：为什么输出 token 比输入 token 贵。后面四则是今天点名的消息。Anthropic 把 Agent Skills 捐给基金会那条，今天不讲。

## 【一次生成分成两段】

模型接到一段输入，并不是从头到尾用同一种算法匀速跑完。第一段叫 Prefill。它把你输入的那些 token 一次并行算完，留下每个 token 的 Key 和 Value，并吐出第一个输出 token。token 一多，就算成很大的矩阵乘法。这一段吃的是 GPU 算力。它决定你多久能看见第一个字，也就是 TTFT。

从第二个字开始是 Decode。每一步只生成一个新 token。可是这一步仍要把整个模型的权重，加上前面已经留下的缓存，从显存里读一遍。算的很少，搬的很多，卡在显存带宽。它决定后面每个字要多久，也就是 TPOT。整段等待大约等于首字时间，加上每个后续字的时间乘以输出长度。

## 【这和报价怎么接上】

输入长、输出短，比如把一篇长文收成一句话，工作主要在 Prefill，算力忙一下就结束。输入短、输出长，比如一句话写一篇长文，Decode 会把这张卡占很久。输出单价更高，对应的就是这段串行占时。

这不是说每家厂商的输出价都必须是输入的某一个固定倍数。倍数要以各家定价页为准。今天要记住的是方向：先看请求是哪一段更重，再拿牌价去对。

两段的优化也不通用。Prefill 可以切块，也可以和 Decode 拆到不同的机器上，这就是 PD 分离。Decode 更在意投机解码、量化和显存带宽。把多个请求组在一起，对 Decode 特别有用，因为同一次权重搬运可以摊给好几条请求。Prefill 已经把算力吃满了，组批带来的好处不是同一种。

## 【今天的四则消息】

第一则是 Jev。它不是上次认错的 Jet。TypeSafe 在 2026 年 9 月 15 日的博文里，把 Jev 写成第一款 System One 模型。它不生成文本。你事先规定好输出的结构，它一次给出带概率的决定。他们公布的价格是每百万输入 token 0.042 美元，输出不加 token 费。博文里的几十倍、上百倍加速，是他们自己的评测，而且他们写了这组数字偏高、工作流是自己团队做的。不能当成我们复现过的收益。

第二则是 Google Cloud 的 Agent Compute Engine。10 月 22 日的博文说，它已经在支撑 Gemini 做工作任务，给客户的预览要到未来几个月。智能体等待的时候，微型虚拟机可以做成快照暂停。服务凭证是在虚拟机外面注入的。20 万个智能体、每秒 500 次激活、暂停和恢复低于 500 毫秒，是 Google 自己的基准。售价没有写。

第三则是 OpenAI 的 Decisions API，同一天宣布一般可用。模型是 GPT-6 Luna，用来做分类、路由、打分这种有界决定。公告价格是每百万输入 token 0.10 美元，缓存后的输入是 0.01 美元，不收输出 token 的费用。这组价格不替换我们已经核实的 GPT-5.6，标准档仍是 4 美元对 20 美元。30 分钟和 12 小时那种缓存写入要多少钱，公告指向另一份定价指南，这次没有准确数据。

第四则是 SGLang 在 AWS Trainium 上的插件进入 beta。Trainium2 和 Trainium3 可以做推理，也可以做强化学习里的 rollout。博文举的例子是：在 Trainium3 上为 Qwen3-MoE 生成 rollout，在一台 H200 上训练。吞吐和单价都没有给，而且现在要申请才能用。

## 【收束】

今天可以带走的一句是：输入便宜，是因为整段可以并行；输出贵，是因为后面每个字都在串行占卡。Jev 和 Decisions API 都在收「只做有界决定、输出不加 token 费」这一类账单。Agent Compute Engine 和 Trainium 则是在问：等待的时候，机器和卡还要不要继续被占着。
